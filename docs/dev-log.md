### 2026-09-25 清晨：屏幕"蒙雾/残影/UI 乱飞"根治（刷屏 NO_MEM）

用户肉眼全程看到残影叠加，而离线截图一直正常——分歧锁定"写屏"环节。
日志翻出铁证：一晚 **736 条** "Draw bitmap failed: ESP_ERR_NO_MEM" +
"spi_master: setup_dma_priv_buffer Failed to allocate"。
- 根因：QSPI 每次刷屏要临时分一块内部 DMA 缓冲（buffer_height 10 行 =
  466×10×2 ≈ 9.3KB）；0.5.0 控件树（设置/面板/鸭子页上百对象）把内部 RAM
  吃到 ~7KB → 9.3KB 永远分不出来 → 每次刷屏静默失败 → 物理屏只剩旧像素
  +零星成功小块（用户看到"雾/花盆/偶尔冒出的数字"）。离线渲染不走这条路，
  所以我的截图一直"正常"。
- 修复：buffer_height 10→4（块 3.7KB 塞得进剩余内存）。压力测试（21 次视图
  切换）刷屏失败 0 次，内部低点 17.9KB。
- 教训：离线截图是"逻辑正确性"的证据，不是"物理输出"的证据——视觉问题
  必须 grep 刷屏失败日志 + 用户肉眼双确认。0.5.0 视觉问题从始至终是这一个
  根因（半透明面板只是叠加在其上的次要观感问题，也已修）。

### 2026-09-25 上午：鸭子声音语言（ADR-037 声音设计）

用户提出"围绕鸭子做音效"：开机/开录"嘎"、发出"嘎嘎"、收到"嘎嘎嘎"、错误"噗噗"（鸭子放屁，用户设计）。
- 全部本地合成零采样：嘎 = 500→250Hz 降调锯齿+包络（190ms/声）；噗 = 70~130Hz
  锯齿随机游走 + 噗呲断续包络（220ms×2）。AudioPipe 新增 quack(count)/poot()，
  作业队列 op 4/5；chime/beep 保留但已被替代。
- 声数=事件类型，闭眼可辨；噗与嘎是两个声音物种（无音高噪声 vs 有音高叫声），
  不可能混淆。开机自检同步改为"嘎"（鸭子打招呼）。
- 修复录音错误提示撞车：原错误提示 beep(2) 与成功收尾音完全相同，用户无法
  分辨发送是否失败——这正是声音语言要解决的问题。
- 待用户耳朵验收：合成音"嘎"够不够像鸭，参数（降调幅度/沙哑度/时长）单行可调。
