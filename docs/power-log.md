# 嘎嘎功耗档案（长期跟踪）

电池：**702530，600mAh**（聚合物锂电，2026-09-25 首装）
计量口径：设备端 AXP2101 电量百分比（BAT_PERCENT 0xA4）。
⚠️ 百分比在 0% 后仍有余量（实测可再跑 ~6 分钟），以"彻底没电"为终点。

## 本基线的解读（2026-09-26）

- 整夜"屏幕常亮 + 一直交互"是**最重负载**，98mA 均耗里屏幕占大头
  （AMOLED 最低亮度约 20~40mA）、BLE 连接态 radio（7.5ms 间隔）其次、
  IMU 500Hz+陀螺再次、CPU/音频间歇。
- 有意义的对比基准：后续每次优化后**同场景复测**（或新增"挂脖静置
  息屏 8 小时"这种日常场景），填新行即可。
- 0% 后余量 ~6 分钟：低电提示阈值（15% 红）之外，AXP2101 的 0% 不是
  真空点——后续可把"真关机电压"保护做进 Power（低于 3.3V 强制深睡）。

## 待验证的优化栈（2026-09-26 已编译未烧）

按预期收益排序（粗估，以实测为准）：
1. 息屏自动熄灭修复（补发风暴撤掉后应恢复）——屏幕是最大头，息屏 8h
   与常亮 8h 差一个数量级
2. 挂脖 10 分钟无连接深睡（<1mA，已是第二层保险）
3. BLE 连接间隔 7.5→30ms（radio 唤醒 ÷4）
4. IMU 息屏 500Hz+陀螺 → 94Hz 无陀螺（传感器电流约减半）
5. 广播间隔 105~305ms（断连等待时的 radio 占空比大降）

## 测量规范（以后照此填表）

- 记录起止时间、起始/结束电量、屏幕状态（常亮/自动熄）、BLE 状态
  （连接/断开）、大致交互频率
- 平均电流 = 600mAh × 掉电% ÷ 用时
- 每次只变一个变量，否则分不清是谁的功劳
